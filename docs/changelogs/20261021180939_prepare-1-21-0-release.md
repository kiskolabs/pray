# Prepare 1.21.0 release

## Participants

- Andrei Makarov

## Decisions

- Promote the existing Unreleased sections to 1.21.0 dated 2026-10-21.
- Keep the release preparation separate from tagging and publishing.
- Keep the changelog focused on tested product behavior. Dependency advisory identifiers and applicability remain in the linked dependency assessment.

## Effects

- `Cargo.toml`, the Rust workspace dependency floors, `Cargo.lock`, `npmjs/pray-cli/package.json`, `npmjs/pray-cli/package-lock.json`, the TypeScript package-version constant, the Ruby version constants, and `rubygems/pray-cli/Gemfile.lock` now agree on 1.21.0.
- `Prayfile.lock` was regenerated with `pray 1.21.0`; its package pins and manifest hash did not change.
- The root, npm, and Ruby changelogs expose the same coordinated version. The npm and Ruby changelogs retain only the changes shipped by those packages.
- The release-note preview contains seven concrete outcome bullets. A prose pass found no marketing language, invented objection, empty contrast, or stray em dash. The dependency claim pass left advisory details in `docs/dependencies/20261021170938_october-2026-security-advisories.md` instead of adding an unsupported broad security promise to the release notes.
- The person-facing surfaces assessed were the 1.21.0 changelog section and CLI version metadata. The heading establishes the release and date before the behavior bullets. There are no interactive, empty, loading, or error states in the document. Long technical bullets wrap on a narrow terminal but retain their subject and recovery meaning. A reader can identify the changed workflows and required Rust version. Final GitHub rendering remains for the release operator to review after tagging.
- The first local npm test and Rust coverage attempts could not bind a loopback port inside the sandbox. The same commands passed with network isolation removed. The first Ruby lint attempt could not write the default RuboCop cache; it passed with `XDG_CACHE_HOME` under the temporary directory. These were execution-environment failures, not product failures.

Validation completed with these commands and observed results:

- `cargo check --workspace --locked`: passed for all four workspace packages at 1.21.0.
- `cargo run -p pray-cli --locked -- install`: completed, updated only `Prayfile.lock`, and left `AGENTS.md` unchanged.
- `./scripts/release/versions_test.sh`: coordinated version tests passed.
- `./scripts/release/changelog_test.sh`: changelog notes tests passed.
- `./scripts/release/crates_status_test.sh`: crate status tests passed.
- `cargo test --workspace --locked`: passed the complete Rust workspace suite.
- `npm test`: passed 269 tests after rerunning outside the loopback-restricted sandbox.
- `bundle exec rspec`: passed 331 examples with Ruby 3.4.10.
- `cargo fmt --all --check`: passed.
- `cargo clippy --workspace --all-targets --all-features --locked -- -D warnings`: passed.
- `npm run lint`: checked 237 files and found no circular dependency across 160 analyzed files.
- `bundle exec rake lint`: inspected 192 Ruby files without offenses and validated RBS signatures.
- `make loc-check`: reported 164 warnings at or above 150 lines and no unratcheted failure above 300 lines.
- `cargo deny check advisories licenses bans sources`: advisories, licenses, bans, and sources passed.
- `npm audit --omit=dev` and `npm audit`: each reported zero vulnerabilities.
- `bundle exec bundler-audit check --update`: updated ruby-advisory-db and reported no vulnerabilities.
