# Prepare 1.26.1 release

## Participants

Andrei Makarov (@amkisko)

## Decisions

Prepare version 1.26.1 dated 2026-11-02. Keep preparation separate from committing, pushing, tagging, publishing, and changing distribution checksums.

Use a patch release for two corrections to 1.26.0 behavior: rendered-destination reconciliation and optional dependency referrals. Coordinate the Rust workspace, npm and JSR packages, Ruby gem, lockfiles, package metadata, release checks, and four changelogs at the same version.

Keep the AUR package at 1.26.0 until a 1.26.1 tag archive exists and its checksum can be measured.

Do not hide the incomplete GitHub record for 1.26.0. The coordinated packages are available from crates.io, npm, RubyGems, and JSR, but the repository has no `v1.26.0` tag or GitHub Release. Decide whether to create that tag at commit `354b6f4` before tagging 1.26.1.

## Effects

All coordinated version declarations and changelogs now identify 1.26.1. The release dry run built or checked the Rust, npm, JSR, and Ruby packages without publishing them.

The npm audit found one moderate `minimatch` advisory propagated through seven development-only entries below `madge`. The production graph is clear, the packages do not include the development graph, and the repository lint commands do not provide the glob configuration that reaches the vulnerable path. The assessment remains visible in the dependency record.

The complete validation record is in the matching changelog note.

The 1.26.1 candidate is not present on crates.io, npm, RubyGems, or JSR. No registry version conflicts block publication.

## Next

- Review the complete change set before committing or publishing.
- Decide whether to create the missing `v1.26.0` tag and GitHub Release at commit `354b6f4` before releasing 1.26.1.
- Reconcile the local `main` commit that is not yet on `origin/main`, then commit and push the prepared 1.26.1 changes.

- Replace the AUR source checksum after the 1.26.1 tag archive exists.
