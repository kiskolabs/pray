# Gate AGENTS.md against drift from .agents/

## Participants

Vesa Vänskä

## Decisions

Add a drift gate to the CI rust job. pray composes its own AGENTS.md from amkisko/* prayers via Prayfile, but no job ran pray verify, drift or install, so the blind spot the tool exists to close was live in its own repo.

Invoke the binary as `cargo run -q -p pray-cli -- drift && status=0 || status=$?` rather than letting the command stand alone. GitHub Actions runs `run:` blocks under `bash --noprofile --norc -eo pipefail`; under -e a non-zero exit terminates the step before any `case $?` can inspect it, which would make the branch carrying the actionable message unreachable.

Match exit 6 specifically. `pray drift` documents "Exits with code 6 when drift is found"; drift_command reaches its other failure modes through resolve_project and read_lockfile, which map to 2, 1 and 3, so 6 here means drift and not a broken checkout.

Set PRAY_NO_VERSION_CHECK so the gate does not call the GitHub releases API on every run. The result is discarded on failure and cannot fail the build, but it is latency and an avoidable dependency on an external service.

Name `pray install` in the failure message, not `pray confess`. confess records an acceptance or rejection for a package confession and submits it to a registry; it is not a local override for a re-render.

## Effects

`pray drift` exits 0 against main as of 2026-09-22, so the gate lands green. The two shell shapes were compared under Actions' own shell: the bare invocation produces empty output and rc=6 or rc=2 on failure, with the case block never reached; the committed shape reaches the drift branch and the infrastructure branch and exits 1 from both. The workflow parses as YAML.
